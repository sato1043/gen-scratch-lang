`rmSync` が非 ASCII 名のディレクトリでプロセスごと落ちる
========================================================

- 日付: 2026-09-03
- 対象: Node v24.12.0 / Windows 11 Pro 10.0.26200（この機械 1 台）
- 出典: 一次情報（最小の再現を書いて実行した）
- 確度: 高（同じ入力を 5 回ずつ実行し、結果は 5/5 で一致）

[読み取りの検査が 40 件走らない記録](./20260903_read-output-tests-crash-midway.md) の
原因である。あちらは症状、こちらは機序を持つ。

## 何が起きるか

```js
mkdirSync(dir)                                  // dir の名前が "置き場"
rmSync(dir, { recursive: true, force: true })   // ← ここでプロセスが消える
```

例外は投げない。`catch` にも入らない。**プロセスが終了コード `3221226505`
（`0xC0000409` = `STATUS_STACK_BUFFER_OVERRUN`）で消える。** 標準出力も標準エラーも
何も残さないので、直前の行までしか手掛かりが無い。

## 切り分け（すべて実測）

| 変えたもの | 結果 |
|---|---|
| `tsx` を外して素の `node` | **同じ**（`tsx` は無関係） |
| 置き場所を `%TEMP%` から作業ディレクトリへ | **同じ**（場所は無関係） |
| `fs/promises` の `rm`（非同期） | **落ちない** |
| `rmdirSync`（空のディレクトリ） | 落ちない |
| ASCII 名へ改名してから `rmSync` | 落ちない |
| ASCII 名のディレクトリの**中**に非 ASCII のファイル・ディレクトリ | 落ちない |

**落ちるかを決めるのは `rmSync` に渡すディレクトリ自身の名前だけで、中身の名前は
関係しない。**

## 名前による違い（実測。規則は未特定）

| 名前 | 結果 |
|---|---|
| `plain` / `café` / `ÿ` | 落ちない |
| `あい` / `アイ` / `置場` / `置` | 落ちない |
| `Ω`（U+03A9） | 落ちない |
| `置き場` | **落ちる** |
| `Ж`（U+0416） | **落ちる** |
| `가`（U+AC00） | **落ちる** |
| 絵文字（U+1F600） | **落ちる** |

**規則を説明できていない。** 文字数でも UTF-8 のバイト数でも分かれず、`Ω` が通って
`Ж` が落ちる理由が立っていない。名前ごとには決定的（各 5 回で一致）なので、乱数や
競合ではない。上流の実装を読んでいないため、機序の特定はここで止めている。

## このリポジトリが踏んでいた経路（直す前）

`src/cli.ts` の `placeAll` に `rmSync` が **1 か所**ある。書き出しが途中で失敗した
ときの巻き戻しで、消す対象は `.<置き場の名前>.tmp-XXXXXX` だった。**置き場の名前が
利用者由来なので、日本語の名前を付けた利用者は巻き戻しの瞬間にプロセスごと落ちていた**
── 申告が出るはずの場面で、何も言わずに消える。

検査の側では `test/read-output.test.ts` の 23 件目がこの経路を通る。そこでプロセスが
落ちるため、**同じファイルの 60 件のうち 40 件が一度も走っていなかった。**

## 直した（2026-09-04・ユーザー裁定）

**staging の名前を最初から ASCII にする**案を採った。置き場の名前を短い要約
（`sha256` の頭 8 桁）へ替え、`.gen-scratch-<要約>.tmp-` の形にする。`rmSync` が
非 ASCII の名前を見る経路が消えるので、改名も非同期化も要らない。

引き換えに、**前の版が残した残骸（`.<置き場の名前>.tmp-`）は拾えなくなる**。残骸を
数えるのは強制終了された後だけなので、影響は「古い残骸が 1 度だけ見えなくなる」に留まる。

退けた案は 2 つ。消す直前に ASCII 名へ改名する案は、`rmSync` の対象が自分で作ったものに
限ることを字面で見張る番人と噛み合わなかった（実際に落ちた）。`placeAll` を非同期にする
案は、公開している関数の形が変わる。

`read-output.test.ts` は **20 件 → 61 件**すべてが走るようになった。

守りは 2 つ置いた ── 名前が ASCII に閉じること、置き場ごとに違い同じ置き場では毎回
同じになること（`test/read-output.test.ts` の `一時ディレクトリの名前が ASCII に閉じる`）。

## 未解決

このリポジトリの経路は塞いだが、**上流の不具合そのものは残っている**。

- 落ちる名前の規則（`Ω` と `Ж` を分けているもの）
- 他の機械・他の Node の版で再現するか（1 台でしか測っていない）
- 上流のどの層で起きているか（`libuv` の `uv_fs_scandir` 周辺が疑わしいが読んでいない）
- 上流へ報告するか（規則を説明できていないので、今の材料では報告に足りない）
