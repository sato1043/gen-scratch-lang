.sb3 の生成
===========

## 概要

記法と作品定義（YAML）から Scratch プロジェクト（.sb3）を組み立てる。記法はスクリプト
しか表せないため、スプライトの構成・変数の初期値・コスチュームの指定は定義が持つ。
同じ入力からは常に同じバイト列が出る。

## 外部仕様(what)

- 記法とプロジェクト定義から .sb3 を生成する。中身の project.json も単体で出せる
- 台帳に無いブロックを含む入力は、該当箇所（記法ファイルと行）を示して終了コード 1 で
  停止する。半分だけ生成した .sb3 を残さない
- 作品定義の知らないキー・値の型の誤り・スプライト名の重複・予約された名前でも停止する
- 記法に書かれた選択肢が台帳の選択肢に無ければ停止する
- 記法の引数の書かれ方（メニュー / 値 / 色）が台帳の引数の種別と噛み合わなければ、
  記法ファイルと行を示して停止する。手掛かりは、綴りが重なるブロックでは別のブロックと
  して読まれた疑いを添える。引数は記法での位置（`%1`）と書かれた綴りで名指す
- 数にドロップダウンが付く入力（`%d.*`）は、書かれ方でなく書かれた値が数として読めるかで
  見る。`[右 v]` も `[右]` も止まり、`(90)` も `(90 v)` も通る
- 同じブロックから複数の申告が出ても、すべてに行番号が付く。同じ綴りの別のブロックは
  別の行を指す
- 作品定義の申告は `project.yaml` と 1 始まりの番号と書き手が書いた名前で指す
- 変数の初期値とリストの要素が文字列・数・真偽のいずれでもなければ停止する
- `スクリプト` が作品のディレクトリの外を指す、または区切りに `\` を使うと、読む前に
  停止する
- 記法・定義・パスに由来する文字列は、制御文字を持ったまま申告へ出ない。表示できない
  符号位置は `<U+001B>` の形の印へ変わる
- 名前から導く変数・リストの ID が別の宣言と衝突する作品は、双方の宣言を示して停止する
- ステージもスプライトも宣言していない定義は停止する（開くが何も起きない .sb3 を出さない）
- 台帳を読めないときは例外で落ちず、他の問題と同じ経路で申告して停止する。構文は正しいが
  中身の型が違う台帳（容器が並びでない・要素が対応でない）も同じ経路で申告する
- 深い入れ子で解析器や描画が再帰の上限に達したときも、依存のソースを吐かずに申告する
- 書き出す前に生成物を Scratch 公式の検証器へ通す。通らないものは書き出さず、終了
  コード 1 で止まり、違反した場所を示す。検証を飛ばす手段は無い。検証は `--format` の
  両方に掛かる
- 同じ入力からは常に同じ .sb3 を生成する
- 生成物の `meta.agent` に生成器の名と台帳の版が入る。台帳の版は上流 2 つの版と、
  手書きの表 3 つ（例外表・ドロップダウン表・影ブロック表）の中身から取った指紋である
- .sb3 を読む側は、`project.json` の展開後が 5 MB を超える入力・ブロックの参照が循環した
  入力・ブロックの中身が壊れた入力を、原因を示して止める。`project.json` は公式検証器と
  同じ規則（1 段のディレクトリまで許す）で探し、当たりが 1 件でなければ読まない
- 台帳の申告は捨てない。申告が 1 件でもあれば終了コードは非 0 になる
- 止まったときは「作品を .sb3 にできない。申告が N 件ある」と述べる。申告の件数を
  「入力の中の箇所」の数と名乗らない ── 台帳の申告もここへ集まるため
- `--help` を付けられる。使い方は標準出力へ出て、終了コード 0 で終わる。空の値を渡した旗は
  既定へ倒れず止まり、使い方の記述に無い旗は受け取らない
- 利用者が自分で作るブロック（`定義` とその呼び出し）を組める。綴りも引数の数も利用者が
  決めるので、台帳は opcode だけを持ち引数は持たない
- ブロック定義に「実行中に画面を再描画しない」指定を与えられる。記法はスクリプトしか
  表せないので、指定は作品定義の `再描画しないブロック` に書く。**記法へ書いたのと同じ形**で
  名前を挙げ、内部の綴り（`%s`）は書かせない
- ブロック定義まわりの書き間違いは黙って通さない ── 挙げた名前が記法に無い・引数を `<>` で
  書いた・引数に名前が無い・綴りの同じ定義が 2 つある・`定義` がスクリプトの途中にある。
  どれも生成物としては成立し公式検証器も通るため、申告しなければ .sb3 を開くまで気づけない
- 記法の行末が CRLF でも綴りに復帰文字が入らない。手で書く記法は追跡下の設定が守らない

## 内部設計(how)

- 中間表現を台帳で opcode へ解決し、project.json を組み立てて zip へ収める
- 引数の並び順は解析器自身の綴りから引き直す。台帳の引数は英語の順に並ぶが、記法は
  日本語の語順で並ぶため、表示の順で素朴に対応させると隣の引数へ値が入る
- 入力の形は影とブロックの有無で 3 通りに決まる。影ブロックが値を置く欄の名前は規則で
  決まり、手書きの表を持たない
- 記法が値を持てないもの（変数とリストの初期値）は定義が宣言し、記法が値を持つもの
  （放送の名前）は記法から集める
- 変数・リスト・放送・ブロックの ID は名前と出現順から導く。無作為な ID を振ると同じ
  入力から同じ .sb3 が出ない
- コスチュームと音は定義がファイル名で指す。属性は 明示 > 導出 > 停止の順に決める
  （`svg` / `png` は寸法から回転の中心を、`wav` はサンプルの率と数を導く。ほかの形式は
  書かせる）。`assetId` は中身の md5 で、ファイル名は参照にすぎない
- 素材を 1 つも書かないターゲットには、自前で生成した最小の SVG を 1 種与える。Scratch の
  既定素材は持ち込まない（配布物へ他者の権利物を混ぜないため）
- zip は時刻・並び・圧縮を固定して決定論を保つ。同じ素材は 1 度だけ収める
- 引数の書かれ方の照合は、引数を台帳の並びへ対応させ終えた位置へ置く。そこでしか記法の
  子と台帳の引数が 1 対 1 で揃わない。数と文字は 1 つの類へ畳む。突き合わせの外に置くのは
  真偽の入力だけで、その件数は検査で固定する。数にドロップダウンが付く入力は、上流に
  ドロップダウンの定義が無いため書かれた値で見る（2026-08-19 に外から内へ戻した）
- 知らない書かれ方は素通しせず申告する。解析器が形を増やしたとき、素通しすると検査が
  静かに効かなくなる
- ID の衝突は導出の形を変えずに検出だけを足す。名前から導くのをやめると同じ入力から
  同じ .sb3 が出なくなる
- 選択肢の照合は表の持ち物だけを見る。素朴に引くと `Object.prototype` の名前が解決済みの
  値として通り、欄が壊れた .sb3 が問題 0 件で出る
- 検証器の呼び出しは 1 か所（`src/validate.ts`）に集める。テストと出荷経路が同じ関数を
  通らないと、テストの緑が出荷の緑を意味しない。検証したバイト列をそのまま書き出す
- 台帳の版の書式は書く側と読む側を同じファイル（`src/catalog.ts`）へ置く。読む側は
  生成器の名で錨を打つ。最初の `{` から読むと、他所の処理系が `agent` に JSON を載せて
  いるだけで自分の刻印と読み違える
- 版は件数でなく指紋で持つ。件数では表の項目を書き換えても動かず、照合が「一致」を返す
- 信頼できない入力への備えは `src/roundtrip.ts` に集める。TASK0002 がこの上に乗る。
  循環の探索は非再帰で、辿る辺の予算が辺の総数と一致するため有限で止まる
- 申告を書く入口は `src/errors.ts` の 1 か所に集める。テンプレートとして呼び、埋め込む値
  だけを必ず中和する。中和は通す側（文字・記号・数・区切り・空白）を数える。入口が 1 つで
  あることは走査が見張り、走査が当てる綴りごとに較正を置く
- 行番号はブロックごとに 1 度だけ引いて覚える。行を引く道具は同じ行を 2 度配らないため、
  覚えないと同じブロックの 2 件目が行を失う
- 引数の綴り（`%n`・`%m.var` 等）の分解は `src/notation.ts` が持つ。呼び名の表は寄せない
  ── 突き合わせの類と書き方の案内では読み手が違い、揃えると片方の読み手が失われる
- 台帳の申告をどう扱うかの規則は `loadCatalog` の doc が 1 か所で持ち、3 つの呼び出し側
  （生成・知識層・読み取り）が同じ規則を通る。分かれてよいのは「成果物を書くかどうか」
  だけである ── 生成と知識層は台帳が欠ければ成果物が欠けるので書かずに止まり、読み取りは
  台帳に無いブロックを印で示す道を持つので読めたところまで書いて非 0 で終える
- ブロック定義の綴り（`proccode`）と引数名は、**解析器が決めた値**（`info.call` /
  `info.names`）から取る。子の部品から組み直すと、解析器が定義と呼び出しを結ぶのに使った
  正規化（大小・空白・記号）をこちらが持たないぶんだけ綴りが割れ、呼び出しがどの定義にも
  結び付かない .sb3 が申告 0 件で出る
- 引数の ID は綴りの要約と位置から導く。綴りをそのまま埋めると、引数 N 個のブロックが
  N 個の ID それぞれに綴り全体を抱えて二乗で伸びる
- 定義と呼び出しの mutation は 1 か所で組む。別々に作ると綴りや引数の並びが食い違い、
  食い違っても構造は正しいので公式検証器が通してしまう

## 自動化できないテスト項目

- Scratch エディタでの動作確認
    - 目的: 生成した .sb3 が Scratch エディタで開き、意図どおり動くか。`meta.agent` に
      文字列が入った状態でも開け、保存し直しても壊れないか
    - 期待結果: 読み込みエラーが出ず、ブロックが意図した並びで配置され、実行すると
      記述どおりに動く。保存し直した .sb3 も再び開ける
    - 観察方法: Scratch エディタ（ブラウザ）へ読み込んで目視と実行
- 公式検証器の版が上がったときの守備範囲の確認
    - 目的: 「何を見て何を見ないか」の記録が古びていないか
    - 期待結果: 検証器が厳しくなれば `test/sb3.test.ts` の表の検査が落ちる
    - 観察方法: 依存を更新して自動テストを走らせる

## 制約・既知の課題

- 公式検証器は構造しか見ない。素材の欠落と実在しない opcode を通す
- **網が `build` の経路に繋がっていることは測っていない**。定義の型検査と名前の検査が
  先に止めるため、検証器まで届く不正な入力を作品定義から作れない。網の部品の側は
  測ってある（受容の裁定 2026-08-18）
- **台帳の版の照合が効くのは、我々が生成し一度も Scratch エディタで保存し直していない
  .sb3 に限る**。エディタは保存のたびに `meta` を作り直し `agent` を上書きする
- 展開量の上限が掛かるのは `openSb3` の経路だけで、生のバイト列を検証器へ直接渡す経路
  には掛からない。入れ子の深さと zip のエントリ数にも上限が無い（TASK0002 で扱う）
- 検証器（`scratch-parser`）は AGPL-3.0-only で、本体依存の閉包で唯一の強いコピーレフト
  である。`private: true` で公開せず提供するのは生成物であるため今は義務が立たない。
  配布またはネットワーク越しの提供を始めるときに再判定が要る
- 検証器の版はどこにも機械可読な形で記録されていない（残課題）
- 画像・音声素材は作らない。利用者が用意した素材の取り込みは扱う（TASK0025）
