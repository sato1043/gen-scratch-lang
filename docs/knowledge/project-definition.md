作品定義の仕様
==============

作品は 1 つのディレクトリで表す。中に定義（`project.yaml`）と、ターゲットごとの
記法ファイルを置く。

```
projects/<作品名>/
  project.yaml     スプライトの一覧・変数とリストの宣言
  stage.sbk        ステージのスクリプト（記法）
  <スプライト>.sbk  スプライトごとのスクリプト（記法）
```

定義は YAML で書き、キーは日本語を使う。記法が表せるのはスクリプトだけなので、
それ以外（スプライトの構成・変数とリストの宣言・位置や大きさ）は定義が持つ。


## 書けるキー

一覧は実装の表から組み立てる。手で書き足しても `--check` が落ちるだけで、
書けるキーは増えない。キーを増やすのは実装の側の仕事である。

## 決まりごと

### 知らないキーは綴りの誤りとして止める

一覧に無いキーを書くと、その場所と書けるキーを示して止まる。キーの綴りを誤ると、
中身の無いスプライトが黙って出来上がり、終了コード 0 で「開くが何もしない」
.sb3 になる。値の型が合わない場合も同じく止まる。

### 変数とリストは定義が宣言する

記法だけでは変数もリストも作れない。宣言の無い名前を記法に書くと、記法ファイルと
行を示して止まる。初期値は定義が持つ。

```yaml
ステージ:
  変数:
    スコア: 0
  リスト:
    記録: []
```

リストの初期値は並びで書く。数や文字を書くと Scratch が開けない .sb3 になるため、
組み立ての前に止める。

### 合図は定義に書かない

合図（メッセージ）の名前は記法から集める。定義に書く欄は無い。送る側と受け取る側で
綴りを揃えれば、それだけで結ばれる。

### 名前から ID を導く

変数とリストの ID は名前から導く。同じ入力から常に同じ .sb3 を出すためである
（Scratch 本体は無作為な ID を振る）。ステージのものは `variable:<名前>`、
スプライトのものは `variable:<スプライト>/<名前>` の形をとる。

このため、名前に `/` を含めると別の宣言と同じ ID になりうる。衝突する組は
組み立ての前に止める。

### ステージとスプライトの名前

ステージの名前は `Stage` に決まっている。定義には書けない。スプライトに `Stage` を
付けることもできない。変数の持ち主を取り違えるためである。同じ名前のスプライトを
2 つ書くこともできない。


## 例

`projects/neko-to-score/project.yaml` が実際に動く例である。

```yaml
名前: ネコとスコア
ステージ:
  スクリプト: stage.sbk
  変数:
    スコア: 0
  リスト:
    記録: []
スプライト:
  - 名前: ネコ
    スクリプト: neko.sbk
    x: 0
    y: 0
```

書けたら組み立てる。終了コードが 0 でなければ、示された箇所を直してからやり直す。

```zsh
node src/cli.ts build projects/<作品名>
```
