申告の質と検査の守備範囲を揃える
================================

## 目的

TASK0003 の CP6 レビューで残った指摘を受ける。止める判断そのものは据え置き、
止めたときに書き手へ何が伝わるか（申告の質）と、検査が何を見ていないか
（守備範囲）を揃える。

TASK0003 では 10 観点のレビューで高 3 件・中 20 件・低 62 件が出た。うち高 3 件と
中 7 件はその場で直し、残りを本作業へ送る裁定を 2026-08-18 に受けた。


## 目標

- 申告が書き手を直し先へ導く（位置情報・語彙・網羅）（SREQ0007）（SREQ0004）
- 検査の守備範囲を実装の側でも狭めない（台帳の中身の検査・要素の型の検査）（SREQ0007）
- 実装の重複した知識（引数の種別の解釈・キーの綴り）を 1 か所へ寄せる
- 散文が名指す数と並びの規則が、実測と食い違わない

## 非目標

- 噛み合い検査の「止める／警告に留める」の裁定を蒸し返さない
- 綴りが重なるブロックの解消（台帳の側の問題であり別の設計が要る）
- 性能の改善（実処理は 5ms 未満で、費用は依存の読み込みが占める）
- 誤りの返し方の形（例外か戻り値か・どの層が受けるか）を決め直さない。形は
  TASK0002 が扱い、本作業は申告の中身の質を扱う（2026-08-19 に裁定）
- `%d.*` にメニューで書ける形を与えない。上流に選択肢の定義が無く、与えるには
  scratch-vm の実行時解釈を出典とする新しい表が要る（2026-08-19 に裁定）
- 定義（`project.yaml`）の行番号を申告へ添えない。`parse` から `parseDocument` へ
  替えると定義の読み方そのものが変わり、影響が本作業の主題を越える


## 問題

引き継いだ指摘を主題で束ねる。CP2 で全件を現物へ照合した結果は作業記録にある。出典は
[TASK0003 CP6 レビューの記録](../records/20260819_task0003-cp6-review.md)
（観点別の詳細レポートは `.claude/tmp/review/20260818-TASK0003/` にあり、追跡外で短命）。

### 申告の質（M10〜M13）

- 同じブロックから 2 件の申告が出ると、2 件目が `行を特定できず` になる。
  行番号を引く道具が綴りで探し、同じ行を 2 度割り当てない作りのため
- 定義側の申告に位置情報が無く、名前があるのに `スプライト[0]` と 0 始まりで指す
- 噛み合いの申告が引数を英字の台帳識別子（`MESSAGE`・`SECS`）で名指す
- `変数` の初期値だけ日本語の申告を持たず、公式検証器の英語スキーマ文へ落ちる
- 記法ファイル由来の制御文字が中和されずに申告へ出る。ANSI エスケープを仕込むと候補の
  一覧を隠せる（TASK0006 の CP6 で実測。2026-08-19 に本作業へ移した）
- 同じものを指す語が「欄」と「フィールド」に割れている。実装は「欄」24 箇所に対し
  「フィールド」2 箇所で、うち利用者が読む面に出るのは申告 `フィールドにブロックを
  差せない` の 1 件。知識層は「欄」で揃っている。「欄」へ寄せる（2026-08-19 に裁定）

### 検査の守備範囲（M6・M7・M15・M16・M20）

- 「読めない台帳」の受け口が JSON 構文までしか守らない。`{}` や
  `{"ブロック": null}` は例外で抜ける
- `スクリプト` の値が作品ディレクトリの外を指せる。仕様には「ディレクトリからの
  相対で書く」と書いたが実装が強制していない
- CRLF の知識層で `--check` が誤診し、writer で直すと改行混在のまま緑になる
  （`.gitattributes` が現状は封じている。`catalog --check` も同形）
- `スクリプト: sub\main.sbk` が Windows で通り Linux で ENOENT。仕様が区切り
  文字を規定していない
- `%d.*` を突き合わせの外へ置いたため、選択肢に無いラベルが素通りする

### TASK0003 の CP6 の低から引き継いだもの（2026-08-19 に走査して選んだ）

観点別レポート 62 件のうち、本作業の主題に当たり未解決の 14 件。残る 48 件は受容と

値域・Unicode 正規化・`--scale` の上限は脅威の想定の外）。

申告の質。

- ID が衝突した宣言の申告だけ位置を持たない。他の定義由来の申告は `スプライト[0]: x`
  と示すのに、衝突は名前の組だけを並べる

- `renderInto` は差し替え前のページの目印は見るが、差し込む本文は見ない。本文へ目印が

- `リスト: "abc"` が申告を 4 件並べる。`Object.entries` が文字列を添字と文字の組へ

- 「知らない形は黙って通さない」が `%b` と `%d.*` の 14 引数で効かない。`mismatchOf` が
  期待の側の null で先に返すため、未知の形がその範囲で素通りする

実装の重複。

- `expectedAs` の綴りの判定が 1 つの関数の中で 2 通りに割れている（生の値の厳密比較と

- `declare()` が収集と検査を兼ねる。定義の検査は `inspect()` に集めてあるのに、ID 衝突の

- `writtenAs` の 2 分岐が到達しない。残すなら保険である旨を書く

数え方と並びの規則。

- 「名前を符号位置の順に比べる」と書いてあるが、JavaScript の `<` は UTF-16 符号単位の

- `expectedAs` のコメントが実測値（`%d.*` は 5 件）を直書きする。台帳が動いても、
  落ちて知らせる仕組みが無い
- 台帳の引数の総数が 127 と 128 の 2 通りで並ぶ。差は `alsoCovers` を含めるかであり
  どちらも正しいが、数え方が数の隣に無い

## 概要設計

問題は 3 つの束に分かれて見えるが、原因はどれも「知識が入口の数だけ散っている」ことに
帰着する。誤りを書く入口・位置を引く規則・引数の綴りを解く判定の 3 つを、それぞれ 1 か所へ
寄せる。以下の D1〜D8 が変更の単位である。

### D1 申告を書く入口を 1 つにする

制御文字が申告へ素通りするのも、復帰コマンドの組み立てが分かれているのも、標準エラーへ
書く入口が散っていることの現れである。今は `src/cli.mjs` に 4 か所
（問題の一覧・案内・未認識ブロックの一覧・`--check` の食い違い）、`tools/cli.mjs` に
3 か所ある。入口が分かれている限り、中和を 1 か所へ足しても他が抜ける。

`src/errors.mjs` へ「申告を 1 件書く」関数を置き、7 か所すべてをそこへ通す。中和はその中で
行う。中和は**許される側を数える**（表示できる文字の範囲を定め、外れた符号位置を可視の
記号へ置き換える）。危ない文字を数え上げる形だと書き手の語彙を先回りできない。

`src/cli.mjs` の復帰コマンドの直書きも、`tools/cli.mjs` の `writeRerun` と同じ関数へ
寄せる。

### D2 位置はブロック単位で 1 度だけ引く

`lineFinder` は綴りで行を探し、同じ行を 2 度割り当てない。この規則は「同じ綴りの別の
ブロックを別の行へ割り当てる」ために要る。ところが同じブロックから 2 件目の申告が出ると、
その規則が巻き添えで効いて 2 件目が行を失う。

直列化の側はブロックを ID で持っている。申告へブロックの同定を添え、行の解決を同定ごとに
1 度だけ行って覚える。同じブロックの 2 件目は覚えた行を返し、別のブロックは従来どおり別の
行を取る。到達基準へ両方を課すのは、片方だけを満たす直し（覚えるだけ・消費をやめるだけ）が
通らないようにするためである。

### D3 定義側の申告に、書き手が書いた位置を与える

`スプライト[0]` は実装の添字であって、書き手が書いた位置ではない。`project.yaml` の名前と
1 始まりの番号で指す（`project.yaml: スプライト 1 番目（ネコ）`）。名前が無いスプライトは
番号だけで指す。ID が衝突した宣言の申告にも同じ位置を添える。

行番号は取らない（非目標）。

### D4 引数の綴りを解く場所を 1 つにする

`%b` / `%c` / `%d` / `%m` / `%n` / `%s` の綴りを解く判定は、読む側だけで
`src/knowledge.mjs`（`typeOf` と `fillArgs`）と `src/serialize.mjs`（`expectedAs` と
`NAMED_KINDS`）の 3 通り、作る側に `tools/build-catalog.mjs` の 2 通りがある。

`src/notation.mjs` を新設し、綴りの分解（前置と種別）と述語を持たせる。各所はその結果を
読む。

**呼び名の表は寄せない。** 今ある 2 系統の呼び名は読み手が違う ── 突き合わせに使う
「メニュー / 値 / 色」（`serialize.mjs`）と、書き方の案内に使う
「数 / 文字 / 条件 / 色 / 選択肢 / 名前」（`knowledge.mjs`）である。同じ対象へ逆の粒度を
求める 2 つの規範に見えるが、扱う段階が違う（前者は台帳との照合、後者は読者への提示）。
片方へ揃えると、切り捨てた側の読み手が失われる。寄せるのは綴りの分解だけとし、呼び名は
各読み手が持つ。この境界を `notation.mjs` の冒頭へ書く。

あわせて `ARGUMENT_TYPES` の素の添字引きを `Object.hasOwn` へ替える（今は
`constructor` で関数が返る）。未知の綴りを黙って通す `?? notation` はやめ、印を返して
公開ドキュメントへ生の綴りが載らないようにする。

### D5 台帳の受け口が形も見る

`loadCatalog` は JSON として読めるかまでしか見ない。容器の型（`ブロック` が配列か）と
要素の型（項目が対応か）を見て、外れたら例外でなく問題として返す。7 形を測ったうち 5 形が
例外で抜けており、受け口を持っているのに使われていない。

### D6 `スクリプト` を作品ディレクトリの中へ閉じる

絶対パス・ドライブ文字・`..` による脱出・区切りの `\` を拒む。`\` を拒むのは、Windows
だけで通り Linux で `ENOENT` になる書き方を、書いた機械の上で止めるためである。仕様
（`TARGET_KEYS.スクリプト` の効き目）にも区切りを書く。

### D7 `--check` が改行の食い違いを名指す

今は生の文字列比較なので、CRLF の作業ツリーでは全ページが「古い」になる。改行だけが違う
ときは改行として名指し、書き戻す側は LF で書く。`.gitattributes` が現状これを封じて
いるが、
封じているのは追跡下の取り出しだけで、`--dir` で外を指せば同じ形が出る。

### D8 `renderInto` が差し込む本文も見る

目印を既定値で補うのをやめ、必ず渡させる。差し込む本文が目印を含むなら書かずに断る。今は
1 回目が書けて 2 回目以降が恒久的に止まる。

### `%d.*` を突き合わせの内側へ戻す

TASK0003 は「数とメニューのどちらで書いても Scratch が受ける」を理由に `%d.*` を突き合わせ
の外へ置いた。CP2 で前提を測り直した結果、上流 `scratch-blocks` は該当の 5 引数をいずれも
`input_value` としてのみ定義し、ドロップダウンを持たない。追跡下の選択肢の表にも、上流から
の導出（19 ブロック / 151 組）にも `%d.*` は 1 件も無い。

`[最後 v] 番目を削除する` は今、`math_number` へ日本語の文字列をそのまま入れた .sb3 を
終了コード 0 で出す。選択肢を台帳へ足すのではなく、`%d.*` を「値」として突き合わせへ戻し、
メニュー記法を止める（2026-08-19 に裁定）。


## 実装計画

段階の順は依存の向きで決める。D1（書く入口）と D2（位置）は後続のすべての申告が通る土台
なので先に置く。D4（綴りの解釈）は段階 2 で足す検査が読むため、段階 2 より前に骨格だけを
入れ、寄せ切りは段階 3 で行う。

| 段階 | 内容 | 含む変更 |
|---|---|---|
