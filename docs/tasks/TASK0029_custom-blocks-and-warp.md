自分で作るブロックを通す
========================

## 目的

カスタムブロック（利用者が自分で作るブロック）を、言葉から使えるようにする。

あわせて、実行中に画面を再描画しない指定（`warp`）を持たせる。重い描画がフレーム数に
縛られる状態を解く唯一の手段であり、これが無いと 3D の描画は実用速度に届かない。


## 目的の外にある事実

2026-09-03 時点。いずれも実測または一次情報で確かめた。

| 事実 | 値 | 出典 |
|---|---|---|
| ペンの描画はフレームに同期する | 1 フレームに 1 本 | [実測](../records/20260903_pen-draw-is-frame-synced.md) |
| 粗い 1 枚（48 本）にかかる時間 | 1.6 秒 | 同上 |
| 解析器は `定義` を読める | `PROCEDURES_DEFINITION` を返す | 記法を通して実測 |
| 台帳に procedures の項がある | **無い**（3 件の申告が出る）| `catalog/blocks.json` |
| scratchblocks に `warp` の綴り | **無い**（走査して 0 件）| `node_modules/scratchblocks/` |
| `:: warp` の印は保たれるか | **捨てられる**（`categoryIsDefault: true`）| 解析して実測 |
| `// warp` の印は保たれるか | コメントとして残る | 同上 |
| 生成側に mutation の組み立て | **無い**（読み取り側だけが持つ）| `src/` を走査 |
| 読み取り側の mutation の前例 | `procedures_call` を組む | `src/read.ts` |
| opcode と引数名 | scratch-blocks に **8 件ある** | `readDefinitions()` を実測 |
| scratchblocks の定義表の `custom` | **0 件**（233 件中）| `commands` を実測 |

**ペンのときと構造が違う。** ペンは固定の 9 ブロックで、opcode と引数名を写せば既存の
台帳の枠にそのまま乗った。カスタムブロックは**利用者が名前も引数の数も決める**ため、
「識別子 → opcode + 引数」という固定の対応表には原理的に収まらない。

### 記法がどう分解されるか（実測）

定義と呼び出しを同じ記法に置くと、5 種類の部品に分かれる。**定義が無いと呼び出しは
`obsolete` になる**（同じ記法の中に定義があって初めて解決される）。

| 部品 | 識別子 | 形状 | カテゴリ |
|---|---|---|---|
| 定義の帽子 | `PROCEDURES_DEFINITION` | `define-hat` | `custom` |
| プロトタイプ | **なし** | `outline` | `custom` |
| 引数の宣言 | **なし** | `reporter` | `custom-arg` |
| 引数の参照 | **なし**（selector は `getParam`）| `reporter` | `custom-arg` |
| 呼び出し | `PROCEDURES_CALL` | `stack` | `custom` |

生成側（`src/serialize.ts`）は `block.info?.id` で台帳を引く 1 本道なので、**識別子を
持たない 3 部品はそこで申告になる**。


## 目標

- `定義` と呼び出しを台帳へ通し、記法から .sb3 を作れるようにする（SREQ0002・SREQ0003）
- `warp` を作品定義から指定できるようにする（SREQ0010）
- 往復（読み取り → 生成）でカスタムブロックと `warp` が保たれる（SREQ0005）
- `warp` の効果を実測し、記録として残す（記録層）


## 非目標

- 3D の作品そのものを作ることは扱わない。手段を用意するところまでを扱う
- 拡張機能ブロック（音楽・micro:bit 等）は扱わない
- 真偽を取る引数（`argument_reporter_boolean`）の記法上の書き分けは扱わない。
  opcode は通すが、記法から真偽の引数を宣言する道は後続で扱う
- カスタムブロックの再帰・相互呼び出しの検査は扱わない（Scratch の側が許す）


## 問題

- **引数が識別子を持たない。** 記法の `(きょり)` は `custom-arg` として読まれ、台帳の枠
  （識別子 → opcode）に収まらない。生成側の 1 本道をどう分岐させるかが要る
- **記法の側の定義が上流の表に無い。** 台帳は scratchblocks の定義表（233 件）を回して
  組み立てるが、そこに `custom` カテゴリは 1 件も無い。`define` は表を通らず構文として
  解析されており、`else` や `end` と同じ層にある。opcode と引数名は scratch-blocks から
  取れる（8 件を実測）ので、手書きが要るのは**記法の側**（識別子・綴り・形状）に限る
- **名前の衝突。** 同じ綴りのカスタムブロックを 2 つ宣言した作品をどう扱うか。ID は名前
  から導く設計なので、衝突すると同じ入力から同じ .sb3 が出る性質と噛み合わない
- **`warp` の効果を実装前に測れない。** `warp` 付きの .sb3 をこの環境から作れないため、
  どれだけ速くなるかは実装後にしか分からない

## 概要設計

### 台帳（FEAT0002）

- カテゴリ `custom` を `LISTED_CATEGORIES` へ、接頭辞 `procedures_` と `argument_` を
  `LISTED_PREFIXES` へ足す
- **opcode と引数名は scratch-blocks から導出する。** 既存の生成元をそのまま使えるので
  写しを増やさない（`procedures_definition`・`procedures_call`・`procedures_prototype`・
  `argument_reporter_string_number`・`argument_reporter_boolean` を実測で確認した）
- **記法の側だけを手書きで持つ。** 識別子・綴り・形状・カテゴリを、pen の
  `EXTENSION_DEFINITIONS` と同じ形の表に置き、`表の出典` へ申告する。上流の定義表を
  回すループでは拾えないため、そこへ合流させる
- **引数が記法から決まることを種別で示す。** ペンで例外表へ `duplicate`・`legacy` を
  足して性質を分けたのと同じ枠を使う。台帳を読む側が「この項の引数欄は空でよい」と
  判定できる形にする

### 生成（FEAT0003）

- `serialize.ts` の識別子解決へ `custom` の経路を足す。識別子を持つ 2 つ
  （定義の帽子・呼び出し）は台帳を引き、持たない 3 つは形状とカテゴリで判定する
- mutation を組む。読み取り側（`src/read.ts`）が既に `procedures_call` の mutation を
  組んでおり、キーの並びと値の形はそこから引く
- 引数の宣言（`outline` の中の `custom-arg`）から `argumentnames` を作り、引数の参照
  （`getParam`）を `argument_reporter_string_number` へ落とす
- ID は名前と出現順から導く。無作為な ID を振ると同じ入力から同じ .sb3 が出ない

### 作品定義

- スプライトのキーへ `再描画しないブロック` を足す。ブロックの名前の並びを取る
- 宣言に無い名前は `warp: "false"` にする（Scratch のエディタの既定に合わせる）
- **宣言した名前が記法に無ければ止める。** 綴りの取り違えを黙って通すと、指定したつもりの
  ブロックが非 warp のまま生成され、しかも生成は成功する

### 読み取り

- `procedures_definition` から記法へ戻す
- mutation の `warp` が `"true"` のものを作品定義の `再描画しないブロック` へ書き出す

### CP6 の裁定を受けた後の追補（2026-09-04）

**検査が途中で落ちていた原因を特定して直した。** 非 ASCII の名前を持つディレクトリを
`rmSync` で消すと Node がプロセスごと落ちる（例外を投げず `catch` にも入らない）。
一時ディレクトリの名前を ASCII に閉じて塞いだ。**同じ経路を利用者も通っていた** ──
置き場に日本語の名前を付けると、申告が出るはずの場面で黙って落ちていた。
機序と切り分けは[記録](../records/20260903_rmsync-crashes-on-non-ascii-dir.md)が持つ。

`test/read-output.test.ts` は **20 件 → 61 件**すべてが走って通るようになった。

**中・低の 4 束も塞いだ**（測り直して残っていたもの。ユーザー裁定）。

| 束 | 実測（前 → 後） |
|---|---|
| C10 同じ綴りの定義が 2 つ | 申告 0 件 → `同じ綴りのブロック定義が 2 つある` |
| C22 全角括弧・二重空白・全角空白 | 3 通りとも止まる → 3 通りとも通る |
| C13 引数 ID が二乗で増える | 引数 3 個で 103 バイト → 64 バイト |
| C11 申告の組み立てが O(W×D) | ループ内で組む → 外へ出した |

**残る 7 束も測って 4 件を塞いだ**（2026-09-04・ユーザー裁定）。

| 件 | 実測（前 → 後）|
|---|---|
| 記法の行末が CRLF | 綴りに復帰文字が入り、LF と混ざると申告 0 件 → 3 通りとも同じ綴り |
| 引数名が空の定義 | 申告 0 件・検証器も通る → `ブロック定義の引数に名前が無い` |
| 定義がスクリプトの途中 | 申告 0 件・前のスクリプトが中身を失う → `定義がスクリプトの途中にある` |
| 呼び出しの引数名 | `["",""]`。「記法からは読めない」の宣言が偽だった → `info.names` から取る |

**測る途中で C3 の見落としが 1 件見つかった** ── `emitCustomBlock` の説明が「今は引数を
取らないブロックだけを扱う」と述べたまま残っていた。前の巡で同じ型の宣言を 4 箇所直したが、
使った走査語（「まだ」「読み取りのみ」）のどれにも掛からなかった。

残りは受容（`serialize.ts` の同居・型注釈・kind の共用・記録の再現性・知識層に `定義` の
記法の例が無い・`N 件目` と `N 番目` の割れ・ID に日本語）。起票は 0 件。

  mutation 無しで型として成立する。`args: null` は既存の「覆わない範囲」の申告と同じ
  意味で、読む側が既に居る
- **`::custom` が 2 つの役を兼ねていた**（2026-09-03）。逆変換器はブロック定義の呼び出しに
  この印を付け、こちらは読み取れないブロックの印（`⟪…⟫::custom`）の目印にも使っていた。
  往復のために前者を落としたら後者の仕組みが壊れ、検査が 5 件落ちた。落とす対象を
  「印の閉じ括弧を持たない行」に限って分けた
- **入れ物の型の検査が重複していた**（2026-09-03）。`再描画しないブロック` が並びでない
  ときに申告を足したが、キーの型を `TARGET_KEYS` から引く共通の検査が既に見ていた。
  同じ書き間違いへ申告が 2 件並ぶので、足した側を落とした
- **スクリプトを持たないターゲットで指定が黙って消えていた**（2026-09-03）。記法を読む前に
  返る道があり、そこで突き合わせを回していなかった。検査を書いて初めて見えた


## 機能への反映

- FEAT0002（ブロックの台帳）: 扱うカテゴリに `custom` が入る。動的な引数を持つ項の扱いが
  外部仕様へ加わる
- FEAT0003（.sb3 の生成）: 作品定義に `再描画しないブロック` が加わる。mutation を持つ
  ブロックの生成が内部設計へ加わる。綴りと引数名を解析器が決めた値から取ることが内部設計に
  加わる（両側で組み直すと定義と呼び出しが結び付かない）
- FEAT0005（.sb3 の読み取り）: 読んだブロック定義を組み立て直せることが外部仕様へ加わる。
  記法に表せない `再描画しないブロック` を作品定義の側へ戻すことと、呼び出しに付く印を
  落とす規則が内部設計へ加わる
