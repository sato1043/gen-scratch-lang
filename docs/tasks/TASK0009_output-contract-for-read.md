読み取りの出力の契約を決める
============================

## 目的

`read` が書き出すディレクトリの扱いを決め、成果物が自分の守備範囲を自分で申告する
状態にする。今は書き出しが逐次で、途中で失敗すると新旧が混ざり、前回の出力が
黙って残る。復元しない属性も成果物の側からは読めない。

TASK0002 の CP6 で 8 観点が独立に指摘した束を受け取る（2026-08-20 に別作業へ
下ろす裁定）。


## 目標

- 書き出しを不可分にする（全部書けるか、1 つも書かないか）（SREQ0008）
- 出力先に前回の成果物が残る場合の扱いを決め、利用者に見える形にする（SREQ0008）
- 復元しない属性を成果物の側で申告する（SREQ0005）
- 要約の対応表から実ファイルへ辿れるようにする（SREQ0005）


## 非目標

- 復元の範囲そのものを広げない。コスチュームと音は FEAT0005 の非目標のまま
- 出力の形式を増やさない（SVG / PNG / markdown / YAML の 4 種を保つ）


## 問題

CP6 の指摘を原因単位で並べる。詳細レポートは短命な `.claude/tmp/` にあり、本節が
起票時点の一次情報である。

**中（8 観点が指摘）**

- **書き出しが逐次で、途中の失敗が新旧の混ざったディレクトリを残す**。`src/cli.mjs`
  が組み立てを全部済ませてから `writeFileSync` を回すが、書き出し自体はファイル
  単位である。ソースのコメントは「全部を組み立ててから書き出す」と宣言しており、
  宣言と実装が食い違って読める
- **出力先を掃除せず、既存を黙って上書きする**。同じ `--out` へ別の .sb3 を読ませると
  前回の `.sbk` と図が残り、要約のターゲット表に無いファイルが並ぶ。どちらが今の
  読み取りの結果かが読み手に分からない
- **復元が属性を申告なく落とす**。重なり順・回転方法・ドラッグ可否・宣言だけで
  使われていないメッセージが `project.yaml` に現れない。とくに重なり順は黙って
  変わるため、組み立て直した作品の見た目が元と違う
- **図の寸法が生成機のフォント計測で焼き込まれる**。SVG は書体を名前でしか参照
  しないので、その書体を持たない機械で開くと文字が枠を越えうる（未実測）

**低**

- 要約の対応表の「ファイル名」列は拡張子の無い幹だけで、実ファイル（`<幹>.sbk` /
  `<幹>-<n>.<形式>`）と字面が一致しない
- 「復元しないもの」の断りがソースの doc にしかなく、`summary.md` にも
  `project.yaml` にも出ない
- 出力が BOM 無し UTF-8。Windows PowerShell 5.1 の `Get-Content` や古い Excel が
  CP932 と誤読する
- 読んだテキストを LF へ揃える規則（`withLf`）が `knowledge` の経路にしか掛からない。
  `read` が書いた `.sbk` を CRLF で `build` へ戻す往復の実害は未実測
- メッセージ（broadcasts）は要約が件数を出すのに `project.yaml` へ復元されない。
  記法の中で使われたものは `build` が作り直すが、宣言だけのものは消える

### TASK0015 の CP6 から下ろしたもの（2026-08-20）

- **図の経路だけ all-or-nothing**。スクリプト 1 本が描けないだけで、読めた記法も要約も
  断りも 1 つも残らない。逃げ道（`--anyway`）の趣旨と正面から反する
- **落としたターゲットが `project.yaml` に痕跡を残さない**まま「作品定義あり」と報告する
- **成果物の断りが日本語固定**で、`--locale en` を選んでも英語にならない
- **逃げ道の来歴が図に無い**。`project.yaml` には印を置いたが、図と `.sbk` は名乗らない
  （記法にはコメントの構文が無く置けないことを実測で確認済み。図は置ける余地がある）

## 概要設計

4 つの指摘（落としたターゲット・描けない図・復元しない属性・検証器が弾いた出自）は
**「落とすなら、成果物の側に痕跡を残す」**の一言で束ねられる。そのうえで
**不可分性は「書き出し」に掛け、「何を書くか」の選別には掛けない**と分ける。この分け方
なら、図の本数の上限で何も書かない既存の裁定（事前の門）と、個別の欠けを申告付きで
落とす扱いが両立する ── 後者は「黙って一部だけ書く」に当たらない。

### 不可分な書き出し（段階 1）

今は `built` へ全部積んでから `writeFileSync` を逐次で回すので、輪の途中で失敗すると
半分だけ新しい状態が残る。doc（`src/cli.mjs`）が守ると宣言した性質を実装は満たして
いない。出力先と同じ親の下へ一時ディレクトリを作り、全部書けてから `rename` する。

出力先が空でなければ申告して止め、`--clean` を渡したときだけ丸ごと入れ替える
（2026-08-21 裁定）。入れ替えは旧を消してから `rename` する。**消してから改名する間に
落ちると旧が消えて新は一時ディレクトリに残る**ので、その窓で失敗したときは一時
ディレクトリを消さず、場所を申告する。

### 落としたものの痕跡（段階 2）

- 図が 1 本描けないとき、今は何も書かずに止まる。その図だけ落とし、申告・要約・
  `project.yaml` の 3 か所へ痕跡を残して他は書く（2026-08-21 裁定）
- 記法へ戻せなかったターゲットは `readSb3` が読み飛ばすだけで、`project.yaml` は
  無言のまま端末が「作品定義あり」と報告する。落とした事実を `reading` が持ち帰る。
  申告の種類の綴りから拾い直さない ── 綴りを変えた瞬間に黙って戻る

### 復元しない属性の申告（段階 3）

`placementOf` が持つ英日の対応（`x` / `y` / `visible` / `size` / `direction`）を、
散文でなく表として括り出す。復元しない属性は**その作品が実際に持つキー**から、この表と
「別の形で復元したもの」（記法・変数・リスト・メッセージ・名前）を引いて数える。
手書きの列挙を持たないので陳腐化しない。表から 1 つ外すと申告の一覧が動くことで
「実装が数えている」ことを破壊で示せる。表の日本語側が `SPRITE_KEYS` に在ることは
検査で見張る（2 か所が割れると片方が取り残される）。

### 対応表と断り（段階 4）

- 要約の「ファイル名」列を実ファイル名（`<幹>.sbk` と `<幹>-<n>.<形式>`）にする。
  形式は要約の側が知らないので、呼び手から渡す
- 書体依存の断りを 1 行足して受容する（実測しない。2026-08-21 裁定）
- 逃げ道の来歴を SVG のコメントへ置く。PNG には書けないので断りへ明記する
  （記法に置けないことは実測済み。2026-08-21 裁定）

### この作業で決めないもの

- `read` の終了コードの契約は TASK0010 が持つ。本作業は「部分的な書き出しを残す」

## 作業記録

### 段階 1: 不可分な書き出しと `--clean`（2026-08-21）

実装したもの。

- `built` が置き場を含む綴りでなく名前だけを持つ形へ変えた（一時ディレクトリへ書いてから
  移す経路で付け替えが要るため）

### 破壊で確かめたこと（2026-08-21）

自動検査へ当てたもの。いずれも名前つきで落ち、落ちた理由まで照合した。

| 外したもの | 落ちた検査 | 落ちた理由 |
|---|---|---|
| 置き場の検分 | 前回の成果物が残っていると止めて何も触らない | 空でない書き出し先へ重ねた |
| 一時ディレクトリ（逐次書き出しへ戻す） | `--clean` で前回の成果物ごと入れ替える | 前回の成果物が残った |
| 移す代わりに写す | 書き出しの後に一時ディレクトリが残らない | 一時ディレクトリを残した |
| 読めない理由の区別 | 綴りがファイルを指していたら止める | ファイルの上へ書こうとした |
| 許可リスト（`ourOutput`） | 読み取りの置き場でなければ入れ替えない | 資料が消えた（ENOENT） |
| 許可リスト（`ourOutput`） | 打った場所とその上を入れ替えない | 止めたのに作業ディレクトリへ書いた |

**「移す代わりに写す」の破壊では、既存の「入力の名前が置き場を決めない」も落ちた。**
一時ディレクトリの残骸を独立に見張っている。

自動検査から書き込みの失敗は差し込めない。ESM の名前付き import は preload での
`fs.writeFileSync` の差し替えを拾わないと実測した（Node 24.19.0）。そのため不可分性
そのものは**ソースを壊す手動の破壊**で確かめた。

- 書き出しの途中で落とす → 置き場は手つかず（前回のファイルが中身ごと残る）、一時
  ディレクトリも残らない
- **対照**（逐次書き出しへ戻して同じ破壊）→ 終了コードも申告も同一のまま、置き場が
  `summary.md`（新）と `前回.sbk`（旧）の混在になった。**申告では見分けが付かず、
  ディレクトリの状態だけが違う**
- 消してから改名するまでの窓で落とす → 旧が消え、組み上がった 6 ファイルすべてが一時
  ディレクトリに残り、申告がその場所を名乗った（設計どおり）

### 実測で分かったこと

**`--out .` の危険は OS で分かれる。** Windows は打った場所の削除を OS が拒むので
（`EPERM`）実害が出ず、Linux では消える。**開発機だけが守られており、CI の Linux は
守られていない。** 許可リストを外した状態で `--out . --clean` を走らせると、Windows では
資料が残り一時ディレクトリだけが増えた。検査は中身の生死だけでなく残骸の有無も見る形に
した ── 生死だけを見ると、この検査は Windows で恒久的に緑になる。

自動検査では到達できない。

そのため、落ちたときに読めた側が残ることは `drawScript` へ細工をして手で確かめた。
記法（`ネコ.sbk`）と描けた図（`Stage-1.svg`）が残り、要約に「図にならなかった

先頭に断りが入り、終了コードは 1 だった。細工の前は 1 つも書かれなかった。
