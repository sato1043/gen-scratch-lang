足した読み替えを見張る
======================

## 目的

TASK0031 で足した読み替え（綴りの重なりを引数の形とカテゴリの明示で解く層）を、機械で
見張れるようにする。今の検査は読み替えが**正しく効くこと**を測るが、**読み替えが増えた
ときに壊れないこと**と**往復が利用者の実際の経路で閉じること**を測っていない。

TASK0031 の CP6（10 観点・103 件）で挙がり、起票と裁定された 3 件を扱う。


## 目的の外にある事実

2026-09-05 時点。TASK0031 の CP6 とその再評価層が実測した。

| 事実 | 値 | 出典 |
|---|---|---|
| 往復の自動検査が通る言語 | **英語のみ**（`toNotation` の既定）| CP6・compatibility |
| `read` コマンドが書き出す言語 | **日本語**（利用者が実際に見る側）| 実測 2026-09-05 |
| ja の往復が今日閉じるか | 閉じる（`::data` は上流が捨て、規則 2 が閉じる）| 再評価層が実測 |
| 規則の `from` の一意性を見張るもの | **無い** | CP6・maintainability |
| 規則が連鎖しないことを見張るもの | **無い**（今は `find` の先頭一致で 1 回だけ当たる）| 同上 |
| 変更前後の実行時間 | 173.5 秒 / 約 174 秒（各 1 回）| TASK0031 の検証 |
| その 2 点が分けられるか | **分けられない**（検査が 11 件増えており、散らばりも未測定）| CP6・performance |

**今は壊れていない。** 3 件とも「壊れたときに気づけない」という形の欠落であり、実害は
出ていない。規則が 3 件で `from` が相異なるうちは順序が結果を決めることもない。


## 目標

- 往復の検査を、利用者が実際に通る言語（ja）でも回す（SREQ0005）
- 規則表の不変条件（`from` の一意性・連鎖の不在）を検査で固定する（SREQ0002）
- 読み替えの追加コストを、散らばりを測ったうえで報告できる形にする（SREQ0002）


## 非目標

- 読み替えの規則そのものを増やさない。見張りだけを足す
- `parseNotation` の署名を変えて台帳の注入口を統一することは扱わない（TASK0031 で受容と
  裁定済み。別の設計が要る）
- 性能の改善は扱わない。測れる形にするところまで


## 問題

- **ja の往復は上流の locale 表に依る。** `parse-sb3-blocks` 同梱の表が変われば閉じなく
  なるが、今は固定する検査が無い。表そのものを検査へ写すと二重管理になる
- **不変条件を検査へ書くと、規則を足す人がその検査を読む契機が要る。** 検査だけ置いても、
  規則を足す側から辿れなければ発火しない
- **時間の測定は散らばりが大きい。** 同じ版を複数回走らせて散らばりを測ってから版どうしを
  比べる必要があり、テスト全体（約 174 秒）を母数にすると読み替えの寄与が埋もれる


## 到達基準

- [ ] 往復の検査が ja でも回り、綴りの重なる 3 件が同じ opcode で戻る
- [ ] 規則の `from` が相異なることを検査が測り、重複を足すと落ちる
- [ ] 読み替えが連鎖しないことを検査が測る（`to` が別の規則の `from` に無い）
- [ ] 上の 2 つが、規則を足す側から辿れる位置にある（`src/disambiguate.ts` の規則表の隣に
      検査の名前を書く、等）
- [ ] 読み替えの追加コストを、同じ版を 3 回以上走らせた散らばりつきで報告する
- [ ] 破壊で確かめる。不変条件の検査は規則を 1 つ足す形の破壊で落ち、ja の往復の検査は
      読み替えを外す形で落ちる
- [ ] 第三者視点レビュー（CP6）を実施するか（提案: **不要**。検査を足すだけで守備範囲が
      狭く、`user-reach` が低い。TASK0031 の CP6 が同じ設計を 10 観点で見たばかりである）


## 概要設計

### 往復（FEAT0005）

`test/roundtrip.test.ts` の `roundTrip` ヘルパへ言語の指定を足し、ja でも同じ検査を回す。
`toNotation` が locale を受けるかを先に確かめる（受けないなら受ける形へ広げる）。

### 不変条件（FEAT0002）

`test/disambiguate.test.ts` へ 2 件足す。規則表の隣（`src/disambiguate.ts` の `RULES` の
直前）に、その検査の名前をコメントで書いて辿れるようにする。

### 測定

読み替えの有無で `parseNotation` だけを回す小さな器を書き、同じ版を 3 回以上測ってから
比べる。テスト全体を母数にしない。
