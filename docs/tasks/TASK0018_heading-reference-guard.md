見出しを名指す参照を見張る
==========================

## 目的

散文が見出しの名前で指している先を、機械で見張れるようにする。

markdown のリンク（`[文言](パス)`）が実在するファイルを指すことは TASK0006 が張った
走査が見張っている。ところが同じ導線の中に、リンクでなく**見出しの名前を文中に書いて
指す**参照がある。これは誰も見ていない。見出しを改名した人には、どこが宙に浮いたかが
見えない。

TASK0017 の CP6 で 3 つの観点が独立にこれを挙げた。同作業が解いた問題（案内した先が
実在するか）と同じ形が、リンクでない参照にだけ残っている。


## 目標

- 見出しを名指す参照を記法として書ける。その記法で書かれた参照は、指す先の見出しが
  消えたり改名されたりしたら検査が落ちる（SREQ0004）
- 記法に落ちなかった参照は捕まらないことを、守備範囲として宣言する（SREQ0004）
- 既存の参照が記法へ載っている（TASK0017 が置いたスキルの 6 件）


## 非目標

- **散文の語から見出しへの参照を推定しない。** 起票時の実測が、この道が塞がっている
  ことを示した（問題節）。推定に頼る検出器は、改名された参照だけを見落とす
- markdown のリンクの書き方そのものを変えない。アンカー（`パス#見出し`）は既存の記法の
  一部で、新しく作るのは規約と検査であって文法ではない
- 記録層（`docs/records/`）を対象にしない。時点の事実を残す追記型のドキュメントなので、
  見出しを改名するたびに過去の記録を書き換える運用にはしない
- 見出しの改名そのものを禁じない。落ちたら参照の側を直す


## 問題

### 見出しを名指す参照を誰も見ていない

TASK0006 が張った走査は、リンクの指す先が実在するかを見る。ただしアンカーは捨てる。

```js
const clean = target.split("#")[0].trim()
```

文中に見出しの名前を書く形（TASK0017 のスキルが持つ「詰まったときに見るもの」と
「自己検査項目」）は、そもそもリンクではないので走査の対象にすら入らない。

着手時に数え直したら 6 件だった（2026-08-24）。起票時の 2 件は目視で拾った数で、同じ
スキルの中に手順書の 4 件と README の 2 件がある。**数えたのが自分の作業対象そのもので
あり、目視で数えた分だけ足りなかった。**

### 語から推定する道は塞がっている

起票時に実測した（2026-08-23。対象は `docs/` と `.claude/skills/` と README の
46 ファイル・見出し 301 種）。

| 測ったもの | 値 |
|---|---|
| 「」で囲まれた語 | 440 件 |
| うち実在する見出しと一致 | 23 件（5%）|
| 一致しない（普通の引用）| 417 件（95%）|

**向きが逆である。** 見出しを改名すると、それを指していた散文は「実在する見出し」と
一致しなくなる。つまり検出器の視界から消える。壊れたものだけが見えなくなるので、
0 件が「健全」と読める。語で分類する設計はここで破れる。

### 記法はまだ 1 件も使われていない

同じ 46 ファイルのローカルリンク 60 件のうち、アンカーを持つものは 0 件だった。
規約を置くところから始まる。

## 概要設計

### 記法

既存の markdown のアンカー付きリンクを使う。新しい文法は作らない。

```
[「詰まったときに見るもの」](../../../docs/knowledge/howto.md#詰まったときに見るもの)
```

読み手には今までどおりのリンクに見え、GitHub 上でも見出しへ飛ぶ。検査だけが `#` 以降を
見るようになる。

### 検査の置き場

`test/guidance.test.mjs` の導線の走査を広げる。いまアンカーを捨てている 1 行を、捨てずに
照合へ回す。走査そのものは既にあるので、足すのは照合と守備範囲の宣言である。

### 見出しの集合の作り方

対象ファイルの `#` 見出しを読み、GitHub のアンカーの作り方（小文字化・空白をハイフンへ・
記号の除去）へ寄せて突き合わせる。日本語の見出しは変換の対象が少ないので、まず素の文字列
での一致を測り、外れる件数を見てから寄せ方を決める。

測った（2026-08-24。導線の 20 ページ・見出し 76 件）。

| 測ったもの | 値 | 決めたこと |
|---|---|---|
| 素の文字列と id が違う見出し | 23 件（30%）| 素の一致では足りない。id 化を入れる |
| 同じ id になる見出しの重複 | 0 件 | 連番の後置（`-1`）は作らない |

差が出るのは番号の前置（`### 6. 生成して検査に掛ける`）と括弧・読点の除去で、日本語
そのものは変換されない。

### 守備範囲

記法に落ちなかった参照は捕まらない。これは実測に基づく設計上の割り切りであり、隠さずに
宣言する（問題節の 2 つめ）。あわせて 2 つを宣言する ── atx（行頭の `#`）だけを見ること、
同じ id が 2 つあるときの連番を作らないこと。どちらも外れたときは黙るのでなく落ちる。

## 検証

### 概要

- 較正を先に置く。記法で書かれた参照が 0 件でも通る検査は、規約が守られていなくても
  緑を返す
- 破壊は改名で当てる。削除で当てると、ファイルごと消えた場合と区別が付かない
- 落ちた理由が見出しの名前を指すことを見る。終了コードだけを見ない

### 検証項目（チェックリスト）

- [x] `npm test` が終了コード 0（460 件・失敗 0・スキップ 0。2026-08-24）
- [x] `npm run typecheck` が終了コード 0
- [x] 較正が空でない。記法で書かれた参照を 6 件拾っている
- [x] 較正が二重。件数の床（6 件）と、別経路で数えた件数との等号を両方置いた
- [x] 較正の実物。一時ディレクトリの入力で、宙に浮いた参照 1 件だけを挙げる
- [x] 破壊 1: 指す先の見出しを改名すると落ちる。理由が見出しの名前を指す
- [x] 破壊 2a: 抜き出しを狭めると較正の床が落ちる
- [x] 破壊 2b: 数える側だけを狭めると等号だけが落ちる
- [x] 破壊のあと対象が無傷（`git diff` が空）
- [x] 改行が LF のまま（3 ファイル）。散文の表示幅が 90 桁以内

### 検証手順

較正と照合。

```zsh
node --test test/guidance.test.mjs
```

破壊は 3 本とも Edit で当てて戻す（スクリプト越しの置換は不一致を成功として返すので、
ソース無傷のまま緑が出る）。

| 破壊 | 当てた場所 | 落ちたもの |
|---|---|---|
| 1. 見出しの改名 | 手順書の `## 自己検査項目` を改名 | 照合。`SKILL.md -> docs/knowledge/howto.md#自己検査項目` |
| 2a. 抜き出しを狭める | 参照の抽出を ASCII の id だけに絞る | 較正の床（6→0）と、一時ディレクトリの較正 |
| 2b. 数える側を狭める | 別経路の計数をページごと 1 件で打ち切る | 等号だけ。床は通り、次の等号で止まる |

2b を分けたのは、等号が本当に両側を突き合わせているかを測るためである。床と実数が
どちらも 6 なので、取りこぼしは今はすべて床で落ちる。等号が塞ぐのは参照が増えた後の
空席で、それは今の実データでは測れない。

破壊 1 は照合の括り出し（下の作業記録）の後にもう一度当て直した。照合のコードを触った
ので、当てていない版で緑を見たことにならない。

### 作業記録

自己コードレビュー（CP5）で 1 件直した。照合の本体が本番の検査と一時ディレクトリの較正で
二重に書かれており、**較正が本番の照合を測っていなかった**（写しを測っていた）。
`lostReferences()` へ括り出し、較正が本番と同じ道を通るようにした。あわせて一時
ディレクトリの入力へ「ページごと無い参照」を 1 件足し、「数えるが照合からは外す」経路も
較正に載せた。


## 機能への反映

FEAT0004（導線の見張り）へ、見出しを名指す参照の照合を足す。外部仕様として増えるのは
2 つ ── 記法（`パス#見出しの id`）と、その形で書かれた参照が指す先の見出しを失うと
`npm test` が落ちること。書き方は README の「ドキュメントの中で見出しを指す」が持つ。
