同じ規則の重複を畳む
====================

## 目的

1 つの規則が 2〜3 か所に別々の綴りで置かれている状態を畳む。今は `project.json` を
探す正規表現が複数あり、「これは zip か」の判定が 3 通りあり、検査の土台が 2 ファイルへ
同一の写しで置かれている。片方を直したときにもう片方が取り残される形が残っている。

TASK0002 の CP6 が「不変条件 6（同じ規則を 2 か所に持たない）の違反」として挙げた束を
受け取る（2026-08-20 に別作業へ下ろす裁定）。


## 目標

- 同じ規則の複数箇所を 1 つへ寄せるか、寄せられないものは一致を見張る検査を置く
- `src/read.mjs` の責務を分け、検査ファイルの分担を読める形にする
- 共有の切り出し口を、呼び手が要るものだけ返す形へ整える


## 非目標

- 実行時の挙動を変えない。同じ入力から同じ出力が出ることを保つ
- 型の宣言を `.ts` へ移さない（TASK0008 が扱う。`Problem` の型の重複はそちらと
  重なるため、着手順を調整する）
- 性能の最適化を主目的にしない。重複の解消に伴って消える無駄は受け取るが、
  測って直す作業は TASK0012 が持つ


## 問題

CP6 の指摘を原因単位で並べる。詳細レポートは短命な `.claude/tmp/` にあり、本節が
起票時点の一次情報である。

**中**

- **`project.json` を探す規則が 2〜3 か所にある**。一致を見張る検査が無く、検証器へ
  渡す経路には第 2 の砦が無い
- **検査の土台（`targetOf`）が 2 ファイルへ同一の写しで置かれ、較正は片方しか
  見張らない**
- **`Problem` の型が 8 か所に書かれている**
- **`src/read.mjs` が 6 責務・700 行超を 1 モジュールに抱える**。変更の影響範囲と
  検査の分担が読めない
- **`definitionProblems` が `build` の課す規則の一部しか持たない**。「組み立てを通る」と
  読める申告が、実際には `build` で弾かれることがある。再現手順（2026-08-20 に実測）:
  値の枠に台帳の知らないレポーターが差さった .sb3 を `read` に渡すと、終了コード 0 で
  「作品定義あり」と出る。その出力先へ `build` を掛けると「台帳に無いブロック」で
  終了コード 1 になる。`definitionProblems` は記法ファイルを読まないので、記法に印
  （`⟪読み取れない: …⟫`）が残っていても定義は通ると判定する

**低**

- 「これは zip か」の判定が経路ごとに 3 通りある（末尾の EOCD を探す・JSZip の
  `loadAsync`・受け入れ検査）
- `definitionProblems` が `{ problems, stage, sprites, declared }` の 4 つを返すが、
  読み取り側は `.problems` しか使わない
- 復元する欄の対応が 2 か所に分かれている（`placementOf` の直書きと `SPRITE_KEYS`）
- `toNotation` と `SCRIPT_GAP` が本番から呼ばれず、呼び出し元は `test/` だけ
- `read()` が 1 関数で 5 役を持ち、入口の定型が 3 度写されている
- 命名が中身を名乗らない（`@typedef Used` ほか）
- `basename(input, extname(input))` を 2 度計算している等の細かな重複
- `reverseOpcodes()` を呼ぶたびに 207 件の `Set` を作り直す（3 か所が個別に呼ぶ）
- 名前の重なりの採番を線形の入れ物で持ち、衝突の件数の二乗になる
- 検査ファイル 3 つの分担規則がどこにも書かれていない
- 検査の母集団に、公式スキーマが許すが自分たちの生成器が作らない形が乏しい

### TASK0015 の CP6 から下ろしたもの（2026-08-20）

- **`Reading` の形が 5 か所の手書きに割れる**。`refused ⊆ problems` の不変条件が暗黙で、
  型は必須と宣言し実装は既定値で埋め検査は省略した literal を渡す（三様）
- **同じ概念に 3 つの語**が当たる（`rejected` / `refused` / `unfit`）
- **`readSb3` が選択肢オブジェクトを丸ごと `openSb3` へ転送**する
- **「弾かれるが読める」フィクスチャが 2 ファイルに複製**されている
- **`cell()` の名前が実態から遅れている**（「表の升」を指すが箇条書きの行でも使う）
- **拒否を二重に持つ**（`refused` と `problems`）
- **床が 1 述語で、その先は場当たりの `?.` と try/catch に依る**
- **ターゲットごとに逆変換器の opcode 表（207 件）を作り直す**
- **USAGE と `parseArgs` の旗一覧を突き合わせる検査が無い**
- **成果物のテキストが CLI の旗名 `--anyway` を直書き**する（内側が外側を知る依存の逆流）


### TASK0010 の CP6 から下ろしたもの（2026-08-22）

同じ規則が 2 か所にあり、片方だけが直っているものを受け取る。

- **`summary.md` の表題行だけが `cell` を通らない**。ファイル名から活きたリンク・生の
  HTML・升の区切りが入る（段階 3 で塞いだ穴と同型が、同じファイルに残っている。実測）
- **`placeAll` の doc は「宣言の無い出力は置かない」と無条件に述べる**が、実際に守るのは
  `read` の口だけである。`build` の書き出しはこの砦を通らない
- **戻り道のコマンドが、打てない綴りで断りなく出る**。`quotedPath` は安全と報告するのに、
  `announce` が中和して綴りを書き換える（実測）
- **opcode の綴りが要約と記法で割れる**（同じブロックが 2 通りに書かれる）
- **同じものの呼び名が 3 通りある**（利用者が読む面での揺れ）
- **`guarded` が配列形のブロックを対応へ作り替える**（形を保たない経路が 1 つ残る）

## 概要設計

起票の段階につき骨子のみ。着手時に CP2 で埋める。

- 寄せられる重複と、寄せられない重複を先に分ける。経路が違うために同じ規則が
  要る箇所（受け入れ検査と読み手）は、寄せずに一致を見張る側へ倒す
- `src/read.mjs` の分割の軸は責務で切る（台帳の照合 / 印付け / 要約 / 定義の復元）。
  行数で切ると呼び合いが増える
- `definitionProblems` は呼び手が要るものだけを返す形へ変え、`build` の規則との
  差分を明示する
