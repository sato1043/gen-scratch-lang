利用者が読む面のコマンドを、実物へ渡して確かめる
================================================

## 目的

README と知識層に書いたコマンドが動くことを機械で見張る。今はエージェント向けの
SKILL.md だけが実物へ渡して照合されており、**人が読む面は誰も照合していない**。

TASK0008 で実装の綴りが `.mjs` から `.ts` へ動いたとき、README・知識層の 11 箇所は
正しく追随した。だがそれは作業者が手で数えたからで、**次の改名では同じ手作業が要る**。
守りの非対称が残っている（TASK0008 の CP6 が指摘）。

## 実測（TASK0008 の CP6・2026-08-25）

- 実物へ渡して照合されるのは SKILL.md だけ
- README・`docs/knowledge/` のコマンド 11 箇所は照合されない
- 今回の追随に漏れは無かったが、それは手で数えた結果である

## 目標

- README と知識層に書いたコマンドの綴りが、実在する入口を指すことを機械で見張る
- 見張りが空振りしないことを較正で確かめる（コマンドを 0 件しか拾わない形にしない）

## 非目標

- コマンドを実際に走らせて出力まで照合しない（重い。綴りが実物を指すかまでを見る）
- ドキュメントの散文の正しさを見ない

## 問題

- **コードフェンスの中は既存の検出器が意図的に除外している。** md-link-check も
  guidance の走査もフェンス内を見ない。フェンスを見る側の器が要る
- **「実在する入口」の定義が要る。** ファイルが在るだけでは足りず、そのコマンドが
  受け付ける下位コマンドかまで見るなら、入口の側が名前を export する必要がある

## 到達基準

- [ ] README と知識層のコマンドが実在を照合される
- [ ] 照合の対象が 0 件でないことを較正が見張る
- [ ] 綴りを 1 つ壊すと落ちることを確かめてある
