支える範囲と上限の較正を揃える
==============================

## 目的

どの実行環境を支えるのかを 1 つに決め、上限の線をその環境の実測から導く。今は
`engines` と CI が Node 24 を宣言する一方で、上限の較正は Node 20.19.1 の実測を
根拠に置いている。支えていない版の数値が線の根拠として残り、「どの版で保証するのか」が
2 通りに読める。自動検査の環境も Linux 1 本で、TASK0002 の中核であるファイル名の
規則の OS 差を一度も測っていない。

TASK0002 の CP6 が挙げた較正と環境被覆の束を受け取る（2026-08-20 に別作業へ下ろす裁定）。
あわせて TASK0008 の CP6 が挙げた CI の起動回数も受け取る（2026-08-25 の裁定）。

**1 つ目の目標は TASK0008 が部分的に先に済ませた。** `engines`・`.node-version`・CI・
`@types/node` の 4 箇所を `>=24.12.0` へ揃え、食い違いを見張る検査を置いてある
（`test/dependencies.test.ts`）。残るのは較正の根拠（Node 20.19.1 の実測）と README の
支える範囲の記述である。


## 目標

- 支える実行環境を 1 つに決め、`engines`・`.node-version`・CI・README・較正の根拠を
  同じ版へ揃える
- 上限の線を導く規則を 1 つに決め、実測値を線の隣に残す
- CI の環境被覆を広げ、ファイル名の規則の OS 差を測る
- 受け入れ検査が見る名前と、実際の読み手が見る名前の出所を揃える
- CI が 1 度の変更で二重に起動する形を畳む（TASK0008 の CP6 が実測。2 つの契機で
  起動し、matrix の行と掛け合わさって 1 回あたり 4 ジョブになる）


## 非目標

- 上限の値そのものを緩めない（緩める判断は測ってから別に裁定する）
- 支える環境を増やすことを目的にしない。musl / arm64 は未検証の宣言のまま残してよい


## 問題

CP6 の指摘を原因単位で並べる。詳細レポートは短命な `.claude/tmp/` にあり、本節が
起票時点の一次情報である。

**中**

- **3 つの上限の「同じ割合（1/10）」が現象としては揃っていない**。同じ割合を名乗るが、
  それぞれが違う現象に対する割合になっている
- **受け入れ検査は zip のセントラルディレクトリの名前を見るが、実際の読み手は
  ローカルヘッダの名前を見る**。名前の出所が違うため、検査が見た名前と読まれる名前が
  一致しない入力を作れる
- **CI が Linux 1 本**。ファイル名の規則（大文字小文字の畳み込み・予約語）の OS 差を
  測っていない。TASK0002 の高 1 件はこの機械の NTFS 上でしか実測できなかった
- **入力ファイルの生の大きさに上限が無い**。展開後の量には上限があるが、読み込む前の
  大きさは無制限である
- **公式検証器が素材（非目標）に対して二乗の検査を回す**。5 MB の線の内側での費用を
  測っていない
- **同じ入力を 2 度処理する**（zip 展開・JSON 解析・グラフ走査が読み取りと検証器の
  経路で重複する）
- **`officialProblems` が呼び手の上限を無視して既定値だけを使う**（要再確認）

### TASK0009 の CP6 から下ろしたもの（2026-08-21）

- **図の本数の上限の時間予算が、`--format png` で約 60 倍外れる**。
  `FIGURE_LIMIT` の doc は「約 9 秒に収まる本数へ線を置く」と宣言し、SVG の
  1 枚 4.6 ms を根拠に 2000 本を置いている。PNG は 1 枚 271〜286 ms
  （2026-08-21 実測。図 200 本で 54.2 / 57.2 秒）で、同じ 2000 本なら
  約 540〜570 秒になる（外挿・未実測）。**同じ線が両方の形式へ掛かっている。**
  `main` も同値で、TASK0009 の差分が持ち込んだものではない（TASK0009 の CP6 で
  性能効率性の観点が実測し、2026-08-21 に本作業へ渡す裁定）
- 図 1 枚の限界費用が本数に依存する。5.71 ms（少数）→ 7.08 ms（多数）で、doc の 4.6 ms を
  上回る。doc は測定条件を書いていないため、機械差か方法差かを切り分けられない

**低**

- 宣言している動作環境（Windows / Linux・Node 24）と、較正に使った実行環境
  （Node 20.19.1）が食い違う
- 「線は最も低い実測の 1/10 に置く」という主張に検査が無く、基準値がコードと作業書で
  食い違う
- 図の余裕（深さ 1200）は Node 24 でしか測っていない。逆変換器の限界は Node 20 と 24 で
  2 割動くことが測られている
- 上限の較正が 1 台の実測に依り、他アーキテクチャ（musl・arm64）の余裕が読めない
- ZIP64 の終端を一律で断る。JSZip は 32 bit に収まる範囲で開ける
- エントリ 0 件の正当な空 zip を「zip として読めない」と断る
- `RESERVED` が上付き数字の装置名（`COM²` 等）を通す。許可リストが `\p{N}` を通すため

### TASK0015 の CP6 から下ろしたもの（2026-08-20）

- **旗ありでは `project.json` を必ず 2 度展開・2 度解析**する。早期の打ち切りが消える
- **O(1) の床が O(project) の検証器の後ろ**に置かれている
- **`FIGURE_LIMIT` の較正が 1 形式ぶんしか無い**（PNG は図ごとに書体を読み込む）
- **`officialProblems` が呼び出し側の上限を受け取らない**。既定値だけを使う
- **「上限は旗に依らない」の一部が既定値依存**で、呼び出し側が緩い上限を渡すと崩れる
- **検査が上流（ajv）の英語文言を逐語照合**している。実装には「文言でなく種別で見る」
  規律があるのに、検査がその外にある。依存の更新で成果物でなく検査が落ちる


### TASK0010 の CP6 から下ろしたもの（2026-08-22）

上限が「掛かっている経路」と「掛かっていない経路」に割れているものを受け取る。線そのものの
較正ではなく、線が届いていない口の話である。

- **上限が端末にしか掛かっていない**。同じ実行で stderr は 500 件で切るのに、要約
  （`summary.md`）は 600 件すべてを並べた。出力は 8.1 倍に増える
  （5.1 MB → 41.4 MB。実測）
- **要約の申告の節に件数の上限が無い**（`announced`・`undrawnSection`・`unfitSection`）
- **`render` の未認識ブロックの一覧に上限が無い**。`announceProblems` を通らないので
  `PROBLEM_LIMIT` が掛からない
- **`PROBLEM_LIMIT` は 1 呼び出しあたりの上限**で、1 実行あたりではない
  （1 実行で最大 4 回）
- **`announceProblems` の上限は件数だけ**で、`linesOf` が展開する行数が抜けている。
  60 KB・1,000 行という導出が、その分だけ崩れる
- **名前の長さの上限が申告の側にしか無い**。成果物の側は無制限で、中和が最大 8 倍へ
  増幅する（未実測の推論）
- **実行時間の上限が無い**。`FIGURE_LIMIT` × `SCALE_LIMIT` の積は未測定（約 2 GB の外挿）
- **最上位の受け口は同期の投げしか捕まえない**。解決されない promise は終了コード 0 で
  「成功」として終わる（未実測の推論）
- **標準出力・標準エラーの EPIPE に受け口が無い**。`--help` を標準出力へ移した変更が
  `| head` を想定内の操作にした

## 概要設計

起票の段階につき骨子のみ。着手時に CP2 で埋める。

- 支える版は EOL を見て決める。Node 20 を支えるなら CI の matrix へ足し、支えないなら
  較正を 24 の実測へ引き直す。どちらでも「支えない版の数値を根拠に残さない」
- 上限の規則は、現象（何に対する割合か）を名指した形で 1 か所へ書く。割合だけを
  揃えても、対象が違えば揃ったことにならない
- CI の OS 拡張は、ネイティブ依存の導入時間が問題ならファイル名の検査だけを走らせる
  軽い job へ分ける

## 検証

### 概要

起票の段階につき骨子のみ。着手時に埋める。

- 上限は**破壊で確かめる**。線を外して超過する入力が通ることを見てから戻す
- CI の OS 拡張は、畳み込みが働く入力（`Cat` と `cat`）で 2 ファイルが残ることを
  各 OS で見る。通ることだけを見ても、その OS で測れているかは分からない
- 「測れなかった」と「差が無かった」を分ける。名前の照合が空だった経路は、超えて
  いないのではなく測れていない
