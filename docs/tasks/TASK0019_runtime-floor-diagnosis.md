要る Node の版を、動かした人へ伝える
====================================

## 目的

下限を満たさない Node で入口を叩いた人が、何が足りないのかを知れるようにする。
今は内部のスタックトレースだけが出る。

TASK0008 で実装を TypeScript のまま動かすようにしたことで、下限は「古くて非推奨」から
「動く / 動かない」を分ける線へ変わった。下限は 4 つの手で守っている ── 宣言
（`engines`）・導入時の強制（`.npmrc` の `engine-strict`）・静的な検査
（`@types/node` の整列）・実行の検証（CI の下限の行）。**このうち利用者が最も踏む
「実行」の面を 1 つも覆っていない**（TASK0008 の CP6 が 2 観点で指摘）。

同じ面に、綴りが `.mjs` から `.ts` へ動いたことによる復帰路の欠けもある。旧い綴りを
打った人には `Cannot find module` しか出ない。

## 実測（TASK0008 の CP6・2026-08-25）

- この機械の既定 `node` は v20.19.1 で、`node src/cli.ts` は
  `ERR_UNKNOWN_FILE_EXTENSION` の内部スタックで終了コード 1。要る版にも
  `.node-version` にも触れない
- `engine-strict` は npm の導入経路しか塞がない。版を切り替えた後・別シェル・
  clone 直後は素通りする
- 旧綴り `node src/cli.mjs` を打つと `Cannot find module` のみ

## 目標

- 下限を満たさない Node で入口を叩いたとき、要る版と直し方が申告として出る
- 旧い綴り（`.mjs`）を打った人が、新しい綴りへ辿り着ける
- どちらもこのプロダクト自身の申告の形（`errors.ts` の入口）に従う

## 非目標

- 下限そのものを動かさない（`>=24.12.0` は 2026-08-25 の裁定）
- バンドラ・トランスパイラを導入しない（TASK0008 の非目標を引き継ぐ）

## 問題

- **版の検査を `.ts` の中へ置いても効かない。** 拡張子の解決で先に落ちるため、
  ファイルが読まれる前に終わる
- **shim を置く形は 2026-08-24 の裁定と衝突する。** `.mjs` の入口を残す案（再輸出）は
  「すべて `.ts` へ揃える」で落としてある。診断のためだけに戻すなら、その裁定を
  再判定にかける必要がある

## 到達基準

- [ ] 下限未満の Node で入口を叩くと、要る版を名指す申告が出る（実測で確かめる）
- [ ] 旧綴りを打った人が新しい綴りへ辿り着ける
- [ ] 上の 2 つが、下限未満の版で実際に動くことを測ってある
- [ ] `.mjs` の裁定に触れる設計を採るなら、裁定を先に受けている
