読み取りの案内を作る
====================

## 目的

`read` へ辿り着く道を作る。実装は済んでいるが、README にも知識層にも載っていない。
外から見た入口の仕様は `--help` の出力にしかなく、この道具を使う人が最初に読む
ドキュメントから新しいコマンドが見えない。止まったときに次の知識層のページを示す
導線も、`read` だけ持っていない。

TASK0002 の CP6 が挙げた案内の束を受け取る（2026-08-20 に別作業へ下ろす裁定）。
TASK0006 が整えた導線と戻り道の続きに当たる。


## 目標

- `read` を README と知識層から辿れるようにする（SREQ0005）
- 読み取りが止まったときに、次に見るページを申告が示す（SREQ0005）
- 上位のドキュメント（憲章・README の冒頭）と、提供された機能の食い違いを解く
  （SREQ0005）


## 非目標

- Scratch の一般的な入門解説を書かない（SREQ0004 の非目標と整合）
- 申告の文言そのものを書き直さない（TASK0010 が扱う層）


## 問題

CP6 の指摘を原因単位で並べる。詳細レポートは短命な `.claude/tmp/` にあり、本節が
起票時点の一次情報である。

**中**

- **`read` が入口（README）にも知識層にも載っておらず、止まったときの案内も出ない**。
  他のコマンドは止まったときに手順書を示すが、読み取りだけ持たない

**低**

- README の冒頭が「日本語のブロック記法を唯一の入力とし」と書く。`.sb3` を入力に
  取る `read` の追加で成り立たなくなった
- 憲章の非目標「既存 .sb3 を読み解く逆方向の解析を主目的にしない」と、BREQ0003 /
  SREQ0005 が実現済みであることが読み合わない。要求の層では正規化済みだが、
  最上位の憲章が追いついていない
- 作業書 TASK0002 の記述に、実装と食い違う数が 2 か所ある（申告の種類の件数・
  逆変換器が使う `console` の口）。完了済みの作業書の精緻化に当たる

### TASK0015 の CP6 から下ろしたもの（2026-08-20）

- **旗の名 `--anyway` が単独では対象を示さない**。名そのものはユーザー裁定済みなので
  差し戻さず、案内の側で補う
- **「逃げ道」の語が利用者の面に出る**。要約の見出しと申告に使っているが、利用者向けの
  ドキュメントに一度も現れない語である

## 検証

### 概要

- 知識層の新ページは既存の検査が自動で見る。`test/guidance.test.mjs` の
  「README から知識層の全ページへ辿れる」が `docs/knowledge` を全数走査するので、
  README からのリンクを忘れると落ちる（起票時の想定は `knowledge --check` だったが、
  網羅を見るのは guidance の側だった。CP2 で確かめた。ページ数の床 15 は現在 20 で、
  1 枚足しても影響しない）
- 申告からの導線は、実際に止めて出力を読む。文言を検査で固定するだけでは、
  示す先が実在するかは分からない
- 憲章・README の改訂は、見出しを名指す参照の検査（アンカーの照合）と目視で見る
