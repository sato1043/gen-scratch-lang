知識層の入口と、誤りからの戻り道をつくる
========================================

## 目的

書いた人が誤りから自力で戻れるようにする。生成器は誤りを見つけて止まるが、
報告は「何が起きたか」で終わり、「次に何をすればよいか」へ繋がらない。
知識層には答えがあるのに、そこへ辿る道が無い。

TASK0001 の CP6 レビューで、止め方（部分出力を残さず終了コード 1・該当行を
示す）は既に固いと評価された一方、復帰路の提示が弱いと指摘された。


## 目標

- 知識層に入口を作り、書いたものから辿れるようにする（SREQ0004）
- 誤りの報告に、直すための手掛かり（候補・書く場所・やり直すコマンド）を添える（SREQ0004）
- 記法を書くのに要る情報（引数の型・選択肢の綴り）を、台帳から知識層へ出す（SREQ0004）
- 手順書の記述を現在の実装と揃える（増えた停止・値の置き場・`build` の
  振る舞い）（SREQ0004）

## 非目標

- 対話的な入力補助（補完・言語サーバ）を作らない
- 誤りの自動修正をしない（示すに留める）
- 申告の位置情報（行番号・0 始まりの添字）と語彙（英字の台帳識別子）は扱わない。
  TASK0007 が受け持つ。本作業は申告に**足すもの**（候補・復帰コマンド・見る先）に閉じる
- 他者の .sb3 を読む経路の申告は扱わない（TASK0002）


## 問題

現状を 2026-08-19 に実測した。実測の方法と数はこの節の各項に添える。

### 知識層への入口（段階 1）

- **イディオム集の 3 ファイルがどこからも辿れない**。README を起点に markdown リンクの
  推移閉包を取ると（フェンス内は除外）、知識層 16 ページのうち 13 に到達し、
  `idioms/data.md`・`idioms/interaction.md`・`idioms/looks-and-sound.md` に到達しない。
  README の「イディオム集」は `docs/knowledge/idioms/` を指すが、そのディレクトリは
  索引ページを持たない。`basics.md` へは README からでなく手順書の
  「詰まったときに見るもの」経由で着く。リンク切れは 0 件
- **手順書の「詰まったときに見るもの」表が 3 行しかない**。実装が持つ停止は 20 種類を
  超える。TASK0003 が増やした停止（引数の書き方が噛み合わない・影を持たない入力に値を
  書けない・選択肢に無いラベル）と TASK0004 が増やした停止（公式検証器が弾いた）は

  README・`USAGE`・手順書の 3 つを確認して 0 件（TASK0004 CP6）

  `生成した層が古い。台帳と一致しない: <path>`
- **出荷経路の検証が弾いたときの出口が、次の一手を示さない**（TASK0004 CP6）。
  検証を飛ばす旗を置かない設計のため、この申告が唯一の出口になる。しかも手順書は
  「示された行を直す」と案内するが、この失敗に行番号は出ない。付随して

      1 つ落とした .sb3 で 5 件中 4 件が重複と `oneOf` だった）

## 概要設計

TASK0001 で作った生成の機構（目印で囲んだ層を台帳から差し込み、`knowledge --check` で
照合）をそのまま使う。新しい仕組みは要らない。

### 導線を検査で固定する

導線は書けば増えるが、放っておくと減る。ページを足した人がリンクを足し忘れても、今は
誰も気づかない。README を起点に markdown リンクを辿り、`docs/knowledge/**` の全ページへ
着くことを検査で見る。既存の `test/dependencies.test.mjs` が「入口から静的に辿れる範囲」を
同じ形で見張っており、その形に倣う。

イディオム集は索引ページ（`idioms/README.md`）を置いて 4 ファイルを並べ、README と手順書は
そこを指す。README へ 4 ファイルを直接並べると、項目が増えるたびに README が伸びる。

### 引数の型は記法の綴りから出す

台帳の引数は記法の綴り（`%n`・`%s`・`%m.*`・`%b`・`%c`・`%d.*`）を持ち、これが手順書の
分類（数・文字・選択肢・条件）と 1 対 1 で対応する。突き合わせに使う `expectedAs` は
数と文字をどちらも「値」として扱うため、そのままでは読者に足りない。

表示用の型は台帳の綴りから出し、その解釈を `knowledge.mjs` の 1 か所に閉じる。引数の種別を
解釈する場所が 3 モジュールに分かれている件は TASK0007 の目標（M14）なので、そちらが
統合するときの対象として増やす場所を 1 つに限る。

| 台帳の綴り | 表示 | 件数 |
|---|---|---|
| `%m.*` | 選択肢 | 45 |
| `%n` | 数 | 43 |
| `%s` | 文字 | 23 |
| `%b` | 条件 | 9 |
| `%d.*` | 数（注意の印つき）| 5 |
| `%c` | 色 | 3 |

件数は `test/serialize.test.mjs` の数え方（`args` + `alsoCovers`・`statement` を除く）に
揃えた計 128 件で、同検査が固定している総数と一致する。散文の件数はこの検査から引き写す。

記法の `%1`・`%2` と台帳の引数の並びは 119 ブロック中 117 で一致する。一致しない 2 件
（`EVENT_WHENBACKDROPSWITCHESTO`・`SENSING_OF`）は引数を取れないブロックとして
「覆わない範囲」に既出であり、表では引数を持たない行として出る。

### 選択肢はセルへ並べ、長いものだけ別掲する

選択肢を持つ引数は 24 件・延べ 157 組ある。1 セルへ全件を並べたときの文字数を測ると、
40 文字を超えるのは 3 件だけである。

| 引数 | 選択肢 | 文字数 |
|---|---|---|
| `EVENT_WHENKEYPRESSED.KEY_OPTION` | 42 | 105 |
| `SENSING_KEYPRESSED.KEY_OPTION` | 42 | 105 |
| `OPERATORS_MATHOP.OPERATOR` | 14 | 60 |
| 残り 21 件 | 1〜7 | 4〜37 |

閾値を超えたものはセルに件数だけを出し、全件はページ末の生成表へ 1 度だけ置く。閾値は
試作して表の見え方を測ってから決め、決めた値と測った実際の幅を作業記録へ残す。折り畳み
（`<details>`）は GitHub の外のビューアで中身が読めなくなるため採らない。

### 報告は台帳の持ち物をそのまま出す

「選択肢に無いラベル」の候補は全件を出す。上限を置かないのは、現在の最長が 105 文字で
1 行に収まるためである。この長さを検査で固定し、台帳が伸びたら落ちるようにする。

`--check` の復帰コマンドは、実際に渡された引数を反映する。`--dir` を渡された
`knowledge --check` が既定の場所を指すコマンドを示すと、示したとおりに打っても直らない。

### 段階 1: 導線（2026-08-19）

- イディオム集の索引（`docs/knowledge/idioms/README.md`）を新設し、README と手順書の

- 手順書の「詰まったときに見るもの」を「止まったとき」（申告 6 行）と「止まらないが
  困ったとき」（2 行）に分けた。申告の名前をコード表記で書き、検査が拾えるようにした
- 手順書の値の置き場を 5 つの型（数・文字・選択肢・条件・色）へ揃えた。散文が「3 つ」と
  書いて 4 行の表を出していた

**破壊を 3 通り当てて 3 通りとも狙った検査が落ちた。** 索引から 1 リンクを消す → 到達性が
落ちる。リンク先を存在しないファイルにする → 到達性とリンク健全性の 2 つが落ちる。表へ
実装の出さない申告を足す → 申告の照合が落ちる。

手順書が挙げる申告は、ソースの grep でなく**実物を動かして**照合する。組み立てて作る申告
（`変数が宣言されていない`）を grep は取り落とすためである。

### 段階 2: 一覧の拡張（2026-08-19）

- ブロック解説の一覧へ引数の列を足した。型の呼び名は手順書の「値と入れ子を埋める」と
  同じ語（数・文字・選択肢・条件・色・名前）にした。`%d.*` は当初「数か選択肢」と

- 一覧の各行へ `%1`・`%2` の番号を出した。台帳の引数は記法の番号順に並び、中身の置き場
  （`statement`）だけが末尾に付くことを 119 件で確かめた
- `test/knowledge.test.mjs` へ 2 件足し、行の数え方を行数から行の形へ変えた。自動テストは
  242 件から 244 件になった

**閾値 40 は測って決めた。** 選択肢を持つ 24 件のうち 40 文字を超えるのは 3 件
（キー 42 件で 105 文字が 2 つ、演算の 14 件で 60 文字が 1 つ）。この値で生成した一覧の

**引数を解けない 2 件は、記法から呼ぶと止まることが分かった。** `背景が [背景1 v] に

**破壊を 3 通り当てて 3 通りとも落ちた。** 型の `%d` の分岐を消す → 型の検査が落ちる。
閾値を 400 にする → 別表の検査が落ちる。`または名前` を落とす → 型の検査が落ちる。
